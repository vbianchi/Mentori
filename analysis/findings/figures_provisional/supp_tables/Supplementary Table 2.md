# Supplementary Table 2 | Generator and judge pairing

Generator and judge for every experiment of this study. Generator names come from the run records in the analysis repository: each run's identity file, or the model field of its answer rows or result rows for Zhang RLM, the stress set-ups and the local-model depth sweep. Model selection reads the three result files of the earlier selection runs, each with several generators, so the row gives their number. The flat wide call and the short-passage single pass name gemini-3-flash-preview from their design, since only their judge rows are in the analysis repository; the component benchmarks and the distiller intervention name the model of each run's single component role. Judge names come from the judge's header files where they are in the analysis repository, otherwise from the study's settings file, experiments/LOCK.toml. devstral-small-2:24b is the main judge. qwen3.8:27b is the second judge and appears only on the rows it judged; its scores are not read here. Records counts stored answers. Files and Records are blank on the second judge's rows: their answers are counted once, on the main judge's row.
