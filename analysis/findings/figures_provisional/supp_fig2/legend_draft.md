**Supplementary Figure 2 | Retrieval pipeline selection.**

**a**, Mean reciprocal rank (MRR) against corpus size (5, 10, 15, 20 and 30 papers, evenly spaced) for four embedding models with dense search only (512-token chunks, overlap 50); one colour and shape per model, labelled at the largest corpus; n = 28 retrieval queries at every size. **b**, MRR against corpus size for seven search strategies with BAAI/bge-m3 embeddings, on the same 28 queries; one colour and shape per strategy. Hybrid (fixed α=0.5) and Hybrid (adaptive α) are equal at every corpus size and are drawn as one line. In a and b, the points at one corpus size are set apart along the axis, one place per series, so tied values stay visible. In b, where two series are tied at neighbouring corpus sizes, only the line drawn last shows between them; the points show every series. **c**, MRR of eight chunking configurations (BAAI/bge-m3, RRF search, 30 papers), each run three times: run 1 on the 28 queries of a, b and d, runs 2 and 3 each on 27 other query ids, no query id shared between runs. One row per configuration, highest mean at the top; each tile gives one run's MRR and the last column the mean of the n = 3 runs, coloured on the scale above. **d**, MRR of RRF (pre-built bge-m3 indexes) search against corpus size (5, 10, 20, 50 and 100 papers, evenly spaced), on the same 28 queries, one run per size; each value is printed above its size. The retrieval queries are a set of their own, not questions of the question-answering benchmark; no answer is generated and no judge is involved.
