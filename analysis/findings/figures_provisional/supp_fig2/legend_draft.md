**Supplementary Figure 2 | Retrieval pipeline selection.**

Each value is a mean reciprocal rank (MRR) over retrieval queries of their own, not questions of the question-answering benchmark; no answer is generated and no judge is involved. Panels a, b and d and run 1 of c use one set of 28 queries. **a**, MRR on n = 28 queries against corpus size (5, 10, 15, 20 and 30 papers, evenly spaced) for four embedding models with dense search only (512-token chunks, overlap 50); one colour and shape per model, labelled at the largest corpus; points at one size set apart along the axis, so ties stay visible. **b**, MRR on n = 28 queries against corpus size (5, 10, 15, 20 and 30 papers, evenly spaced) for seven search strategies with BAAI/bge-m3 embeddings; one colour and shape per strategy, labelled at the largest corpus; points at one size set apart along the axis, so ties stay visible. Hybrid (fixed α=0.5) and Hybrid (adaptive α) are equal at every corpus size and are drawn as one line. Where two strategies tie at neighbouring sizes, only the line drawn last shows between them. **c**, MRR of eight chunking configurations (BAAI/bge-m3 embeddings, RRF search, 30 papers), each run three times: run 1 on n = 28 queries, runs 2 and 3 each on n = 27 other query ids, no query id shared between runs. One row per configuration, highest mean at the top; each tile gives one run's MRR and the last column the mean of the n = 3 runs, coloured on the scale above the tiles. **d**, MRR on n = 28 queries against corpus size (5, 10, 20, 50 and 100 papers, evenly spaced) for RRF (pre-built bge-m3 indexes) search, one run per size; each value is printed above its size.
